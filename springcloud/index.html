三条主线：

  1. 注册/发现流：应用启动 → WebServerInitializedEvent → AbstractAutoServiceRegistration.start → ServiceRegistry.register → 实例进入注册中心；消费侧 DiscoveryClientServiceInstanceListSupplier 拉取实例列表 → 经缓存/健康检查过滤器链 → RoundRobinLoadBalancer 选出一个 ServiceInstance。
  2. 请求流：外部请求 → RoutePredicateHandlerMapping 匹配 Route → FilteringWebHandler 执行 GlobalFilter + 路由过滤器 → lb:// 被 ReactiveLoadBalancerClientFilter 换成真实 URL → NettyRoutingFilter 用 Reactor Netty 发出 → 响应由 NettyWriteResponseFilter 回写。另一条：@FeignClient 代理方法 → SpringMvcContract 产出的 MethodMetadata → RequestTemplate → RequestInterceptor → FeignBlockingLoadBalancerClient 选实例并改写 URL → 真实 Client。
  3. 配置流：spring-cloud-build parent 定版本 → 各 -dependencies BOM 定模块版本 → 自动配置通过 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports 注册 → @ConfigurationProperties（spring.cloud.gateway.server.webflux.*、spring.cloud.openfeign.client.*、spring.cloud.loadbalancer.*）覆盖默认 → 运行期 RefreshRoutesEvent / RefreshScopeRefreshedEvent 触发路由重建。

面试速通：Spring Cloud 高频问题一页纸

易错点与面试坑

  • 5.x 的 Gateway 不再是”WebFlux only”：starter 按 server 类型拆成 -server-webflux 与 -server-webmvc，spring-cloud-gateway-server 模块只剩一个配置元数据 JSON，Java 代码全在另两个模块里。 面试答”Gateway 基于 WebFlux、不能进 Servlet 容器”已经过期——5.x 起两种 server 类型各有 starter。 连带坑：引用路径写错模块名会直接找不到文件；本文深读的是 webflux 实现，请求模型是 ServerWebExchange。
  • 过滤器没有”全局先、路由后”：FilteringWebHandler 把 GlobalFilter 和 GatewayFilter 放进同一个 list 再按 order 排序。 没有显式 order 的路由过滤器 order = 声明下标 + 1，且 defaultFilters 永远在前——YAML 里的书写顺序就是执行顺序。 同理别搞反方向：多路由竞争时 lookupRoute 取首个命中（filterWhen + next()）。 而一个 Route 内的多个 predicate 之间是 AND——全部命中才算匹配，书写顺序不影响结果。
  • predicate 抛异常会被吞掉当 false：lookupRoute catch 住异常只记 error 日志，一个坏 predicate 不会让网关 500。 排错时要去日志里找 “Error applying predicate for route”，而不是等一个 500——该 Route 会被当成没匹配上，继续试下一条。 与之对照，过滤器链没有这种静默：index 越界返回 Mono.empty()；顺序错了只会”该改的没改到”，不会报错。
  • Feign 写了 url 就一定不走服务发现：getTarget 会特意识别并 unwrap 掉 FeignBlockingLoadBalancerClient（及其重试变体）取 delegate。 即使 classpath 上有 loadbalancer 也一样——“配了 url 又想按服务名调用”是自相矛盾的配置。 记忆点：url 有无是运行期分岔点；没有 Client Bean 时报错会提示缺 starter-loadbalancer。
  • Feign”属性优先”是默认行为：defaultToProperties 默认 true，yml 会后应用并覆盖 @Configuration 里定义的 ErrorDecoder / Retryer / Options。 yml 里配的 requestInterceptors 是追加不是替换——“我的拦截器没生效”先查这条。 loggerLevel、超时、重试器等几乎每一项都能按 client 名字单独配，不用写 @Configuration 类。 想让配置类赢过 yml，就把 spring.cloud.openfeign.client.default-to-properties 设成 false。
  • FeignClientFactoryBean 里禁止 @Autowired（类注释 WARNING）：FactoryBean 创建时机与常规 Bean 注入存在竞态，依赖全部手动 getBean。 logger / encoder / decoder / contract 四类必需 Bean 缺失时直接抛 IllegalStateException，启动即失败，不是运行期才炸。 记忆点：每个 Feign client 一个子上下文，Bean 查找走子上下文 + inheritParentContext 继承语义。 inheritParentContext=false 时严格只看子上下文——跨 client 共享 Bean 的写法会失效。
  • 三个消费方无实例时失败语义各不相同：Feign 返回 503 响应、Gateway 抛 NotFoundException、阻塞 LB 抛 IllegalStateException。 限流场景还要再分一层：空 key 默认 403（denyEmptyKey），被限流默认 429。 再加上 NettyRoutingFilter 的超时 504——四个状态码对应四种失败，排错时别记混。
  • 5.x 没有 RoutesRefresher：路由刷新走 RefreshRoutesEvent → CachingRouteLocator.onApplicationEvent，缓存用 CacheFlux，支持按 metadata 局部刷新。 management 子上下文和 LoadBalancer 子上下文的刷新都不触发路由重建，否则每个服务级子上下文创建都会引发一次全量重建。 刷新完成回发 RefreshRoutesResultEvent，失败也发（带 Throwable）不静默。 触发入口之一是 POST /actuator/gateway/refresh；RouteRefreshListener 还监听上下文刷新与心跳事件。

第一讲：Spring Cloud 是什么与 release train

定位

Spring Cloud 不是一个「框架」，而是一组独立发版的 Spring Boot 子项目加上一套统一版本协调机制（release train）。这一讲回答三个问题：版本怎么对齐、commons 为什么是所有子项目的地基、starter 到底是什么。

1.1 release train：三个仓库怎么对齐版本

证据 1 —— 共同的 Maven parent。三个仓库根 pom.xml 都把 parent 指向 org.springframework.cloud:spring-cloud-build:5.0.3：

  • spring-cloud-commons/pom.xml:13-18
  • spring-cloud-gateway/pom.xml:16-21
  • spring-cloud-openfeign/pom.xml:13-18
<parent>  <!-- spring-cloud-commons/pom.xml:13-18；gateway:16-21；openfeign:13-18 三处相同 -->

    <version>5.0.3</version>

这就是 release train 的机械实现：train 版本 = spring-cloud-build 的版本。谁想进这一列车，就把 parent 指到这个版本。三个仓库各自 <version>5.0.3</version>（spring-cloud-commons/pom.xml:8、spring-cloud-gateway/pom.xml:9、spring-cloud-openfeign/pom.xml:7）与 parent 同号，不是巧合，而是 train 的约定。

第一讲小结：Spring Cloud 是”版本列车 + 一组契约”，不是单体框架

第四讲：OpenFeign —— 声明式客户端与动态代理

定位

OpenFeign 把”写一个 interface + 加 @FeignClient”变成”能发 HTTP 请求的 Bean”。本质是：在 Spring 的 BeanDefinition 注册阶段塞一个 FactoryBean，运行期由它用 Feign 的 Feign.Builder.target(...) 生成 JDK 动态代理。

Spring Cloud OpenFeign 相对原生 Feign 增加了四件事：

  3. 每个 client 一个子 ApplicationContext —— FeignClientFactory
  4. 接上 Spring Cloud LoadBalancer —— FeignBlockingLoadBalancerClient

  5. OpenFeign：FeignClientsRegistrar → FeignClientFactoryBean.getTarget → Targeter → SpringMvcContract → FeignBlockingLoadBalancerClient（第四讲）
  6. 横向对照：把”Gateway 的 lb 解析”与”Feign 的 lb 解析”放在一起看——两者最终都落到第二讲的同一套 ReactorLoadBalancer

复习卡

版本/模块：

版本/模块： train 的实现机制 = 三个仓库共用 spring-cloud-build:5.0.3 作 parent；BOM 不只管自家模块，还锁被包装的第三方（feign-bom / okhttp-bom / bc-jdk18on-bom）；5.x 的 gateway 拆成 -server-webflux 与 -server-webmvc，spring-cloud-gateway-server 模块只剩一个配置元数据 JSON；starter-openfeign → starter-loadbalancer → spring-boot-starter-cache + evictor 决定了”服务名调用 + 实例缓存”是默认能力。

commons / 负载均衡： ServiceInstance 只有 getServiceId() 是非 default，新增能力都用 default 方法加；ReactiveDiscoveryClient.probe() 已 Deprecated(forRemoval = true)——返回 void 却调 Flux 是历史 bug，改用 reactiveProbe()；@EnableDiscoveryClient(autoRegister=false) 是往 Environment 加 property source（addLast），不是硬关闭；AbstractAutoServiceRegistration 用 port.compareAndSet(0, ...) 保证只有第一个 WebServer 事件能写端口；ServiceInstanceListSupplier 链是装饰器模式，DelegatingServiceInstanceListSupplier 连生命周期和 selectedServiceInstance 都向下传播；DiscoveryClientServiceInstanceListSupplier 的三重防御（Flux.defer + 30s timeout + onErrorResume）都降级为空列表；CachingServiceInstanceListSupplier 用 CacheFlux，LoadBalancerCacheManager 不可用时原样返回 delegate 只 WARN；RoundRobinLoadBalancer 的 position 用 incrementAndGet() & Integer.MAX_VALUE 做无锁环形计数且单实例不推进；阻塞与反应式的分界线只有一处——BlockingLoadBalancerClient.java:163 的 .block()。

Gateway： RouteDefinition 是配置态（@NotEmpty predicates），Route 是运行态六元组，uri() 里 localhost 当 scheme 会显式报错；RoutePredicateFactory 是 @FunctionalInterface，名字由类名推导；快捷配置靠 shortcutFieldOrder() + shortcutType()（Path 用 GATHER_LIST_TAIL_FLAG）；一个 Route 的多个 predicate 是 AND；无 order 的路由过滤器 order = 声明下标 + 1 且 defaultFilters 永远在前；lookupRoute 用 filterWhen + next()，predicate 抛异常当 false 只记日志；getAllFilters 把 global 和 route 过滤器放进同一个 list 排序；三个关键 GlobalFilter 的 order 是 10000 → 10150 → LOWEST；ReactiveLoadBalancerClientFilter 按 ReactorServiceInstanceLoadBalancer marker 类型查 LB，找不到抛 NotFoundException；NettyRoutingFilter 只把响应放进 CLIENT_RESPONSE_ATTR（延后提交），超时映射 504；限流空 key 默认 403、被限流默认 429；5.x 没有 RoutesRefresher，刷新走 RefreshRoutesEvent → CachingRouteLocator.onApplicationEvent，支持按 metadata 局部刷新并回发 RefreshRoutesResultEvent。

OpenFeign： @FeignClient 接口注册的是 FeignClientFactoryBean（FactoryBean.OBJECT_TYPE_ATTRIBUTE 保证按类型注入可用）；FeignClientFactoryBean 里禁止 @Autowired（类注释 WARNING），依赖全部手动 getBean；defaultToProperties 默认 true → yml 覆盖 @Configuration；有 url 时 unwrap 掉 FeignBlockingLoadBalancerClient 取 delegate——写 url 就不走服务发现；接口上不允许 @RequestMapping，直接抛 IllegalArgumentException；方法未指定 HTTP method 默认 GET，GET + 无注解参数会 WARN”可能退化成 POST”；yml 里配的 requestInterceptors 是追加不是替换；无可用实例时 Feign 返回 503 响应、Gateway 抛 NotFoundException、阻塞 LB 抛 IllegalStateException——三个消费方的失败语义各不相同。
